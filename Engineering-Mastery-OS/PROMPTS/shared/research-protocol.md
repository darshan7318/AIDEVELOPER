# Adaptive Web Research Protocol

## When to research
Research when a claim is current, version-sensitive, unfamiliar, disputed, security-related, platform-dependent or materially improved by external evidence.

## Source hierarchy
1. Official product/framework documentation.
2. Specifications and standards.
3. Official source repositories and release notes.
4. Academic papers and recognized technical publications.
5. Established engineering publications.
6. Community discussions for practical experience and counterexamples.

## Workflow
1. Convert the learning goal into precise research questions.
2. Identify the learner's current understanding.
3. Search targeted queries.
4. Open primary sources and inspect relevant sections.
5. Compare conflicting evidence.
6. Search again if important gaps remain.
7. Summarize in original language.
8. Provide citations and direct URLs.
9. Label assumptions and unresolved uncertainty.
10. Convert the findings into an experiment or implementation exercise.

## Adaptive query changes
- Generic results → add exact API, version, error or runtime component.
- Conflicting results → search official docs/specification/source code.
- Old results → restrict to current release documentation.
- Missing internals → inspect source code, design notes or technical talks.
- Performance claims → require benchmark methodology and comparable environment.
- Security claims → verify current advisory and affected versions.

## Stop condition
Stop when the question is adequately supported by authoritative evidence or when further evidence is unavailable. State uncertainty rather than overclaiming.

Never fabricate source URLs, release details, CVEs, benchmarks, company interview attribution or tool results.
