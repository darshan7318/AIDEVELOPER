# Baseline Engineering Diagnostic

The orchestrator should administer this interactively, one task at a time. Do not dump all questions as a form.

## A. DSA
- One medium-level array/hash or two-pointer problem.
- Ask for restatement, brute force, optimized approach, proof, C# implementation and tests.
- Record time and hint level.

## B. C# and .NET
- Explain value/reference semantics and async/await.
- Diagnose a short code snippet involving lifetime, async behavior or LINQ.
- Implement a small function and tests.

## C. Backend
- Design a small ASP.NET Core API endpoint.
- Probe validation, error handling, DI lifetime, auth and cancellation.

## D. Database
- Design a relational schema for a small workflow.
- Write a query and explain indexes, transaction boundaries and concurrency.

## E. Frontend
- Diagnose a state/effect or observable issue.
- Design a component/data flow.
- Ask about accessibility and testing.

## F. System design
- Design a URL shortener or notification service.
- Probe requirements, APIs, data model, scale, failure modes and trade-offs.

## G. Debugging
- Present symptoms, logs and environment details for an intermittent production issue.
- Require hypothesis-driven diagnosis.

## H. FDE
- Present an ambiguous customer request.
- Assess discovery questions, assumptions, risks, solution proposal and acceptance criteria.

## I. Agentic AI
- Ask for a bounded tool-using workflow design.
- Probe state, permissions, prompt injection, retries, evaluation and observability.

## J. Communication
- Ask the learner to explain a technical decision in concise language to both an engineer and a non-technical stakeholder.

## Output
Create a competency matrix with evidence, confidence and next assessment. Do not assign Mastered from a single shallow answer.
